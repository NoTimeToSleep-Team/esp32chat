## Дополнение 2: debug-режим подтверждений (временно, по запросу)

- **3 ступени на каждое действие**: (1) действие отправлено — клиент шлёт `X-Debug-Trace` заголовок; (2) ответ сервера получен — фиксируется статус и время; (3) подтверждение — клиент отправляет отчёт об успехе на `/debug/api/client-event`. Сервер дополнительно сам логирует каждый трассированный запрос (stage=`server`, с длительностью).
- **Красные плашки**: любая ошибка действия показывает красную плашку с кнопкой OK внизу экрана — плашка НЕ исчезает сама (ждёт нажатия). Каждая такая плашка логируется на сервере (stage=`toast`).
- **Хранение**: таблица `debug_events` (миграция `0023_debug_events.sql`): время, stage, trace_id, action, method, status, ok, stages_done (0–3), error, длительности t1/t2/t3, user_login, ip.
- **Просмотр**: `admin.html → System → Debug Log → Load last 100` (таблица с цветовой индикацией) или `GET /debug/api/events?session_token=...&limit=N` (admin/модератор) c `trace_id=` для поиска конкретного действия.
- **Смысл ступеней при разборе**: 1/3 — действие не дошло до сервера (сеть/клиент); 2/3 — сервер ответил, но ответ не подтверждён/ошибка; 3/3 — полный успешный цикл. Видно и сравнение: есть server-строка с тем же trace_id (дошло) или нет.
- Покрытие трассировкой: SPA (все `api()`-вызовы и загрузка файлов), статический логин/гость, admin.html (apiCall и логин). Проверено на RPi: 17 клиентских трасс — все 3/3, 19 серверных записей; деплой с миграцией 0023, cache-buster поднят (`v=1789900500`).
- Отключение, когда дебаг закончится: убрать `debugReport`/`X-Debug-Trace` в `app.js`/`templates`/`admin.html` и роутер `/debug` в `main.py` (данные в `debug_events` можно чистить).

## Дополнение 4: регистрация и валидация телефона

- **Причина «не даёт создать аккаунт»**: на входной странице формы регистрации не было вообще (только вход/гость), а сообщения об ошибках были невидимы — у `.login-error` в CSS стоял `display:none`, а код лишь снимал класс `hidden`. Исправлено: на странице входа появилась ссылка «Нет аккаунта? Зарегистрироваться» (переключение вход/регистрация, поле телефона), а `.login-error:not(:empty){display:block}` делает ошибки видимыми. Плюс API-ошибки Pydantic (422) теперь показываются читаемо вместо «HTTP 422».
- **Валидация телефона**: серверная проверка формата (10–15 цифр, опциональный `+`; скобки/дефисы/пробелы нормализуются), клиентская проверка до отправки, понятное сообщение об ошибке. Телефон необязателен («No Phone» → NULL), но если указан — должен быть валидным. Невалидный: `422 invalid_phone`; пример валидного: `+7 (999) 123-45-67`.
- Проверено на RPi: API (422/200/200 + очистка) и браузерный прогон 20/20 (форма регистрации, ошибка на плохой номер, тоггл назад). Локально: API 92/92, UI 44/44.
