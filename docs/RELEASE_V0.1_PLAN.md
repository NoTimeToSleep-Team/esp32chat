## 1. Что выпускаем

- v0.1 — **только серверная часть** (`server/`): веб-чат и те разделы, что останутся после обрезки (см. §6). Устройства (Cardputer и др.), прошивки, bridge, аппаратный агент — **вне релиза**, их код не трогаем.
- Цель: рабочая «нулевая» версия, ставящаяся на Raspberry Pi 4/5 в 1–2 команды, с красивым мастером настройки.
- Баги признаны; релиз выходит как **pre-release** с честным списком известных проблем.
- Платформы: Raspberry Pi 4/5, Raspberry Pi OS **64-bit, Bookworm и новее** (Python 3.11+).
  - Bullseye 64-bit (Python 3.9): серверу нужен Python ≥3.10 — установщик не падает, а вежливо объясняет и подсказывает обновиться до Bookworm.
- Версия: тег `v0.1.0`; внутренняя версия кода приводится к `0.1.0` (сейчас 0.6.6 в `server/pyproject.toml` и `server/app/main.py`).
- Живая плата (старая раскладка `/home/gamecat/lc-server`) остаётся как есть; v0.1 — **только чистые установки**; миграция — отдельно после v0.1. _(ожидает явного подтверждения)_

## 2. Зафиксированные решения (обсуждение 11.10.2026)

1. Способ установки — **curl-вариант**: одна команда, логика установки не переписывается после обновлений (schema-driven, §4).
2. Мастер настройки — **whiptail** (мини-CLI: окна, маска пароля, выборы, сводка, прогресс).
3. **Мастер — часть установки**: запускается сразу после неё. Повторно — `lc setup`. Для неинтерактивных развёрток — флаг `--no-setup`.
4. Дефолты (всё меняется в мастере): порт **18080**; SSID точки **LC-Hub**; точка доступа **включена**; регистрация **свободная**.
5. Раскладка установки: `/opt/local-chat-server`, служебный пользователь `localchat`, systemd-юнит `local-chat-server`.
6. Секреты (session secret) и служебные параметры **генерируются автоматически** — лишнего у пользователя не спрашиваем.
7. Установщик должен **сам готовить себе место**: проверить ОС/архитектуру/Python/пакеты/место на диске, доустановить недостающее через apt, пережить занятый apt-лок (ожидание + повторы), не падать молча — при неустранимой проблеме объяснить причину и следующий шаг.
8. Идемпотентность: повторный запуск = апдейт; частичный прогресс сохраняется; данные не затираются.

## 3. Пользовательский сценарий

### Установка (одна команда)

```bash
curl -fsSL https://github.com/NoTimeToSleep-Team/esp32chat/releases/latest/download/install.sh | sudo bash
```

- `install.sh` — «вечный» бутстрап (~30 строк): скачивает релизный тарбол последней версии, проверяет sha256, распаковывает и запускает `install.sh` из него. Правки логики едут с релизом, сама команда не меняется.
- `LC_VERSION=x.y.z` — установка конкретной версии. До первого GitHub-релиза бутстрап можно обслуживать из `raw` ветки `main`.
- Шаги установщика: preflight → доустановка пакетов из манифеста → раскладка в `/opt/local-chat-server` → venv + pip (с повторами) → генерация `app.env` (случайный session secret) → systemd enable/start → health-check с прогрессом → запуск мастера.
- Лог установки — в файл (например `/var/log/lc-install.log`); ошибки — человеческим текстом.

### Мастер (whiptail, запускается сразу после установки)

Экраны: приветствие → проверки → админ (логин/пароль, маска, повтор) → Wi-Fi точка (SSID/пароль/канал/страна) → домашний Wi-Fi (сейчас или позже) → порт (18080) → режим регистрации → сводка → применение (создание админа, AP, рестарт) → финал (адрес портала, доступы, команды).

- Esc на любом шаге — отмена без изменений.
- Повторный запуск `lc setup` — текущие значения подставляются как дефолты.

### Обслуживание

- `lc update` — новый тарбол поверх старого; `data/` и `app.env` сохраняются; недостающие настройки дописываются дефолтами; миграции БД применяются самим сервером при старте.
- `lc backup`, `lc logs`, `lc uninstall`.

## 4. Schema-driven установка (требование «подстраиваемости»)

Вся изменяемая часть — в манифесте; скрипты — generic-движки, которые манифест читают.

`server/setup/settings-schema.json` (едет в релизном тарболе): apt-пакеты, минимальная версия Python, поля мастера, действия после применения.

Правило: **новый параметр сервера = новая запись в манифесте; скрипты установщика и мастера не трогаем.**

Эскиз манифеста (конкретные ключи сверить с кодом при реализации):

```json
{
  "min_python": "3.10",
  "apt_packages": ["python3", "python3-venv", "python3-pip", "curl", "rsync", "whiptail", "ca-certificates"],
  "fields": [
    {"key": "LCS_PORT", "section": "portal", "label": "Порт портала", "type": "int", "default": 18080, "min": 1, "max": 65535, "required": true},
    {"key": "AP_SSID", "section": "wifi", "label": "Имя Wi-Fi сети (точка доступа)", "type": "text", "default": "LC-Hub", "maxlen": 32, "required": true},
    {"key": "AP_PASSPHRASE", "section": "wifi", "label": "Пароль Wi-Fi (8–63 символов)", "type": "password", "minlen": 8, "maxlen": 63, "required": true},
    {"key": "AP_CHANNEL", "section": "wifi", "label": "Канал Wi-Fi", "type": "choice", "choices": ["auto", "6", "11"], "default": "auto"},
    {"key": "AP_COUNTRY", "section": "wifi", "label": "Страна (регуляторика Wi-Fi)", "type": "text", "default": "RU", "maxlen": 2},
    {"key": "LCS_REGISTRATION_MODE", "section": "access", "label": "Регистрация", "type": "choice", "choices": ["open", "closed"], "default": "open"}
  ],
  "actions": ["create_admin", "apply_ap", "restart_service"]
}
```

Компоненты: `install.sh` (бутстрап), `server/scripts/install_pi.sh` (движок установки), `server/setup/wizard.sh` (рендер whiptail), `lc` (команды).

Проверка приёмки: добавить тестовое поле в манифест → мастер показывает его без правок скриптов; убрать поле → не показывает.

## 5. Постоянные настройки сервера

| Настройка | Ключ | Кто задаёт | Дефолт |
|---|---|---|---|
| Логин админа | (учётка) | мастер | `admin` |
| Пароль админа | — | мастер (обязательно) | — |
| Порт портала | `LCS_PORT` | мастер | `18080` |
| Bind | `LCS_HOST` | фикс. | `0.0.0.0` |
| SSID точки доступа | `AP_SSID` | мастер | `LC-Hub` |
| Пароль точки | `AP_PASSPHRASE` | мастер (если AP вкл.) | — |
| Канал / страна | `AP_CHANNEL` / `AP_COUNTRY` | мастер | `auto` / спросить |
| Домашний Wi-Fi (интернет) | uplink | мастер или админка позже | — |
| Режим регистрации | (mode API) | мастер | свободная |
| Session secret | `LCS_SESSION_SECRET` | авто | генерация |
| Рейт-лимиты, логи | `LCS_*` | авто | из `pi.env.example` |
| Данные | `LCS_DATABASE_URL` / `LCS_STORAGE_ROOT` | фикс. раскладкой | `/opt/local-chat-server/data` |

Примечание: отдельной настройки «имя хаба» в сервере нет (ближайшее — SSID точки). Добавить — маленькая доработка, необязательно. Не путать «имя хаба» и SSID.
