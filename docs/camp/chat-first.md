# Camp chat-first: решение и первый срез

Статус: первый вертикальный срез, 2026-11-13.

## Решение

Выбран вариант **B — chat-first пересборка**, а не доработка светлого дашборда.

Причины:

- сейчас camp-панели и чат не связаны: camp-операции не живут в ленте;
- camp-операции — отдельные страницы, поэтому интерфейс ощущается набором инструментов;
- импорт создаёт `camp_people`, но не связывает людей с чатами;
- политика лагеря не enforced в обычном чате.

Новый `/camp` — тёмный чат-шелл на токенах и компонентах `app.css`. Чат — дом, операции — поверх него.

**Граница продукта (решение пользователя):** `/camp` остаётся отдельным
приложением. Мы **не сливаем** его с основным чатом и не меняем основной чат.
Из чата берём только основу: тёмные токены, layout, ленту, composer,
WebSocket, auth, unread/attachments. Серверный chat-engine и API могут быть
общими; оболочка, навигация и UX — свои. Это сознательный выбор, а не
недоделанный merge.


## Информационная архитектура

- **Слева** — смена, каналы отрядов и персонала, быстрые входы «Сегодня / Заявки / Тревоги».
- **В центре** — лента чата, композер и закреплённая карточка переклички для вожатого/директора.
- **Справа** — контекст: сводка, действия, открытые заявки/тревоги. На мобильном — шторка.
- **Действия** — правая шторка или кнопка в карточке; это не отдельные маршруты.
- **Технические экраны** (сеть, состояние, киоски, зоны) в новый основной интерфейс не входят.

## Что уже реализовано в первом срезе

- `GET /camp` отдаёт новый `camp-chat.html`.
- `POST /camp/api/chats/bootstrap` создаёт/синхронизирует:
  - «Персонал» — директор и все staff-роли;
  - «Отряд N» — вожатые и дети отряда с `user_id` + директор.
- `GET /camp/api/chats` возвращает каналы с учётом роли и отряда.
- Новый UI:
  - вход через обычный `/auth/login`, без отдельного токена;
  - список каналов, лента сообщений, WebSocket, отправка;
  - карточка переклички в ленте канала отряда: старт, отметки, «Все на месте», закрытие с причиной;
  - шторки «Заявки», «Тревоги», «Дневник», «Импорт», «Ворота», «Питание»;
  - импорт CSV ростера с preview/commit/undo; после импорта каналы пересобираются;
  - мобильная раскладка: drawer каналов, bottom sheet действий.
- Старый `camp.html/camp.js/camp.css` сохранён в репозитории как legacy, но `/camp` его больше не отдаёт.

## Роли в первом срезе

- ребёнок: свой канал отряда (если создан), «Позвать вожатого», дневник;
- вожатый: канал отряда + персонал, перекличка, заявки, дневник;
- директор: все каналы, перекличка, заявки, тревоги, импорт, дневник;
- охрана: персонал, ворота, тревоги;
- медик: персонал, медицинская тревога, питание;
- родитель: дневник/согласия, без списка чужих детей;
- кухня: питание.

## Универсальность

Универсальность — не «сделать всё для всех», а вынести различия лагерей в
конфигурацию, не переписывая ядро под каждый лагерь.

- **Смена и отряды** — произвольное число, названия и типы из данных, не из кода.
- **Роли** — шаблоны (директор, вожатый, ребёнок, родитель, охрана, медик,
  кухня) + настраиваемые права; медучреждение/лагерь может добавить роль.
- **Карточки** — единый объект `kind + state + owner + deadline + payload +
  actions + audit`; перекличка, заявка, тревога, выдача, дневник, платёж — это
  типы карточек, а не отдельные страницы.
- **Импорт/экспорт** — профиль маппинга колонок, dry-run, идемпотентный upsert
  по внешнему ID, отчёт об ошибках, обратный экспорт. Колонки не хардкодим.
- **Политики** — тихие часы, ЛС, медиа, возрастные полосы, выдача, хранение:
  профиль настроек на смену/лагерь.
- **Офлайн** — очередь операций с idempotency key и видимым статусом; бумажный
  fallback.
- **Один экран — одно главное действие**; остальное — в контексте карточки.
- **Без внешних AI/GPS/face recognition** и без обязательного облака.

MVP получает разумные дефолты для одного лагеря, но модель данных не запрещает
второй лагерь, вторую смену, другие названия отрядов и другой CSV.

## Бумаги: P0 от paperwork

До живого лагеря нужны:

1. Модель оператора ПДн и ответственный.
2. Отдельные согласия: ПДн ребёнка, медданные, фото/видео, дневник, выдача.
3. Медданные/аллергии — отдельный ограниченный доступ, не свободный текст в чате.
4. Выдача ребёнка — доверенные взрослые, документ, причина override, append-only gate log, офлайн-проверка.
5. Инциденты/тревоги — append-only, учения отдельно.
6. Роли и аудит доступа; персональные токены, отзыв.
7. Сроки хранения, экспорт, purge, бэкапы.
8. Договор и статус оплаты — минимум, без бухгалтерского движка.

Ключевая фишка по paperwork: **единый журнал ребёнка + цифровое согласие и выдача**. Не CRM, а доказуемая безопасность: кто забирает, какие ограничения, что было за смену, какие согласия подписаны, аудит смены одним файлом.

## Бухгалтерия

Импорт: ростер (ФИО, дата рождения, отряд, контакты, льготы, номер договора, статус оплаты), доверенные взрослые.
Экспорт: ростер со статусами, отчёт по оплатам, договоры, отчёт смены.

Не строить: налоги, кассу, эквайринг, зарплату, замену 1С. Нужен обезличенный пример файла и ответ, кто владелец данных.

## Похожие системы: обзор research-агента

Полный отчёт: [research-market.md](research-market.md). Ниже — рабочая выжимка.

| Класс | Примеры | Что берём | Чего избегаем |
|---|---|---|---|
| Camp management | CampMinder, CampBrain, CampSite, UltraCamp | регистрация, billing, health, отчёты, родительский портал | десятки модулей и админ-дашборд как главный экран |
| Health/medical | CampDoc | медформы, аллергии, eMAR, ограниченный доступ | свободный текст медданных в общем чате |
| Parent communication | Bunk1, Brightwheel, Procare | ежедневный отчёт, фото, check-in/out, push | отдельное приложение и второй чат |
| Shared inbox/ops | Front, Missive, Slack/Teams | канал, назначение, статус, совместная работа | каналы без объектов и без аудита |

Общий паттерн рынка: **учёт и формы — в вебе, общение — в отдельном parent app/портале**. Camp Edition может выиграть, если соединит их: канал = место работы, карточка = объект, действие = кнопка в карточке, журнал = аудит.

Источники для этой выжимки: campminder.com, campbrain.com,
guideflow.com/blog/camp-management-software, campium.com/blog/top-5-camp-management-software-2025,
support.campmanagement.com (attendance/authorized pickups), mybrightwheel.com
(attendance/check-in). Полный отчёт с Bunk1, CampDoc, Front/Missive и
конкретными ссылками — в `research-market.md`.

Анти-паттерны:

- 20 модулей на верхнем уровне;
- чат как вставная панель;
- свободные ЛС детей и взрослых;
- медданные и коды выдачи в общей ленте;
- отчёт только в Excel без аудита;
- импорт, который не создаёт аккаунты и каналы.

## Следующий шаг

1. **Не сливать** `/camp` с основным чатом; развивать отдельную оболочку на
   основе чата. Общий только серверный chat-engine/API.
2. Универсальные карточки: аддитивная миграция `chat_messages.kind/payload_json`
   (или отдельная `camp_cards`) + состояния/владелец/аудит; перекличка, заявка,
   тревога, выдача, дневник.
3. Импорт → `users` → `camp_people` → каналы; профиль маппинга CSV/XLSX,
   dry-run, идемпотентность, обратный экспорт.
4. Enforce camp-политики в chat-engine (ЛС ребёнок–взрослый, тихие часы, медиа,
   пересылка), не меняя основной UI.
5. Медданные/согласия/выдача — отдельные таблицы, слои доступа, append-only
   журнал; ребёнок/родитель не видят карточку персонала.
6. Бухгалтерия: только после реального обезличенного файла; сначала статус
   оплаты и ростер, без 1С-коннектора и налогового движка.
7. Убрать legacy-панели из навигации после проверки среза.
